# rag-sprints

Hands-on builds of 12 RAG architectures (plus a naive baseline). Each one runs on the same corpus and is scored by [eval-harness](https://github.com/adityajadhavv18/eval-harness).

| Week 1 | Week 2 |
|---|---|
| 00 Naive baseline ✅ | 06 Corrective RAG ✅ |
| 01 Hybrid RAG ✅ | 07 Self-RAG ✅ |
| 02 Parent-Child RAG ✅ | 08 Agentic RAG ✅ |
| 03 Contextual RAG ✅ | 09 GraphRAG ✅ |
| 04 RAG Fusion ✅ | 10 RAPTOR ✅ |
| 05 Adaptive RAG ✅ | 11 Multimodal RAG |
| | 12 Speculative RAG |

## Setup

This repo depends on `eval-harness` through a relative path, so **clone both repos side by side**:

```bash
git clone https://github.com/adityajadhavv18/eval-harness.git eval_harness
git clone https://github.com/adityajadhavv18/rag-sprints.git rag_sprints
cd rag_sprints
cp .env.example .env          # add your OpenAI and LangSmith keys
uv sync
uv run scripts/download_10ks.py   # optional: re-fetch the raw SEC filings
```

## Corpora

Every sprint runs on either corpus. The environment variable `RAG_CORPUS` picks the data folder, the golden set and the Qdrant collection (`<architecture>_<corpus>`):

| `RAG_CORPUS` | Data | Golden set | Chunks |
|---|---|---|---|
| `medical` (main corpus from sprint 01) | `data/medical/`: a **synthetic, fictional** hospital (formulary, lab catalog, protocols, device manuals, leaflets…), generated by `scripts/generate_medical_corpus.py` | `golden_medical_v1.jsonl` | 147 |
| `10k` (default; used as a held-out check) | `data/`: the latest 10-K filings for Apple (FY2025), Microsoft (FY2026) and Tesla (FY2025), fetched from SEC EDGAR by `scripts/download_10ks.py` | `golden_v1.jsonl` | 476 |

The medical corpus is fictional test data, not medical guidance. It is built to separate retrieval methods: near-identical codes (`HV-RX-2047` vs `HV-RX-2074`), fault codes reused across device manuals, look-alike drug names, and plain-language questions over technical text.

```bash
RAG_CORPUS=medical uv run week1/01_hybrid_rag/run_eval.py
```

## Results so far (medical corpus)

| Architecture | Evidence recall / MRR | Context recall | Faithfulness | Answer relevancy | Refused although answerable | Latency p50 | Cost / query |
|---|---|---|---|---|---|---|---|
| 00 Naive (baseline) | 0.75 / 0.54 | 0.75 | 0.93 | 0.69 | 5 / 26 | **1.0 s** | $0.00035 |
| 01 Hybrid (dense + BM25 + RRF) | 0.88 / 0.69 | 0.90 | **0.94** | 0.78 | 3 / 26 | **1.0 s** | $0.00036 |
| 02 Parent-Child (search small, read big) | 0.77 / 0.59 | 0.74 | 0.92 | 0.69 | 6 / 26 | 1.1 s | **$0.00022** |
| 03 Contextual (LLM note per chunk + hybrid) | 0.92 / 0.75 | 0.92 | 0.92 | 0.85 | 1 / 26 | 1.2 s | $0.00031 |
| 04 RAG Fusion (4 rephrasings + RRF) | 0.96 / 0.83 | 0.96 | 0.92 | 0.85 | 1 / 26 | 3.1 s | $0.00040 |
| 05 Adaptive (LLM router + search loop) | 0.92 / 0.75 | 0.91 | 0.92 | 0.85 | 1 / 26 | 3.0 s | $0.00049 |
| 06 Corrective (chunk grader + refine and retry) | 0.96 / **0.86** | 0.95 | 0.91 | **0.90** | **0 / 26** | 2.6 s | $0.00056 |
| 07 Self-RAG (answer checker + wider search / rewrite) | 0.96 / **0.86** | 0.96 | 0.90 | 0.87 | 1 / 26 | 2.7 s | $0.00074 |
| 08 Agentic (LLM picks search / exact lookup, max 5 rounds) | **1.00** / 0.71 | **0.97** | **0.94** | **0.90** | **0 / 26** | 2.5 s | $0.00080 |
| 09 GraphRAG (graph walk + hybrid; +$0.094 one-off index) | 0.92 / 0.68 | 0.92 | 0.91 | 0.83 | 1 / 26 | 1.1 s | $0.00036 |
| 10 RAPTOR (collapsed tree: chunks + 22 summaries; +$0.016 one-off index) | 0.88 / 0.71 | 0.90 | **0.94** | 0.81 | 2 / 26 | 1.1 s | $0.00031 |

Every architecture refuses all 4 unanswerable questions (abstention 1.00). Faithfulness differences are within the judge's error: sprint 07 found that the low scores come from the judge misreading correct answers, not from made-up facts.

The golden set is all fact lookups. Sprint 09 adds chain questions (one fact leads to the next) and sprint 10 adds broad thematic questions; their results are in those sprints' READMEs. On the thematic questions RAPTOR ties Contextual and GraphRAG (7 of 25 points each).

Details and findings are in each sprint's README.

## Checks

One script per eval-harness phase, run with `uv run <script>`: `check_config.py`, `check_schema.py`, `check_golden.py`, `check_runner.py`, `check_metrics.py`. `check_golden.py` takes an optional golden set and data folder, for example `uv run check_golden.py golden_medical_v1.jsonl data/medical`.
